# 跨会话内存连续性系统

基于EvoMap资产（69.15分）实现的改进记忆系统

## 问题分析

### 当前问题
1. **会话间上下文丢失** - 不同会话间记忆不连续
2. **重启后失忆** - 代理重启后丢失上下文
3. **记忆碎片化** - 信息分散在不同文件中
4. **缺乏优先级** - 所有记忆同等重要

### EvoMap解决方案
- **RECENT_EVENTS.md** - 24小时滚动窗口
- **每日记忆** - 当天重要事件
- **长期记忆** - 永久重要信息
- **自动加载** - 会话开始时自动加载

## 系统设计

### 三层记忆架构

#### 1. 最近事件层 (24小时滚动窗口)
- **文件**: `RECENT_EVENTS.md`
- **保留时间**: 24小时
- **内容**: 所有事件的时间线
- **更新**: 每次事件后追加
- **清理**: 每天自动清理超过24小时的内容

#### 2. 每日记忆层 (当天重要事件)
- **文件**: `YYYY-MM-DD.md`
- **保留时间**: 永久
- **内容**: 当天的重要事件摘要
- **更新**: 每天结束时总结
- **特点**: 结构化、有摘要

#### 3. 长期记忆层 (永久重要信息)
- **文件**: `MEMORY.md`
- **保留时间**: 永久
- **内容**: 用户偏好、重要事实、项目上下文
- **更新**: 手动或自动标记重要信息
- **特点**: 结构化、可搜索

### 自动加载机制

#### 会话开始时自动加载：
1. **最近24小时事件** - 了解最新上下文
2. **今天的重要事件** - 了解当天进展
3. **长期记忆** - 了解用户偏好和项目上下文

#### 智能摘要生成：
1. **事件聚类** - 相似事件分组
2. **重要性评分** - 基于频率、用户交互等
3. **摘要生成** - 生成简洁摘要

class EnhancedMemoryStore extends MemoryStore {

### 事件数据结构
```typescript
interface MemoryEvent {
  timestamp: string;      // ISO格式时间戳
  type: string;          // 事件类型: user_message, system_action, etc.
  content: string;       // 事件内容
  importance: number;    // 重要性评分 0-1
  tags: string[];        // 标签
  metadata: Record<string, any>; // 元数据
}
```
