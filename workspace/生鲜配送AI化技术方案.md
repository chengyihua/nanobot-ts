# 生鲜配送SaaS系统AI化技术方案

## 一、项目概述

### 1.1 项目背景
现有生鲜配送SaaS系统需要人工操作录单、对账、报表等流程，效率低下且容易出错。通过AI Agent技术实现自然语言交互，让客户可以直接与AI对话下单，AI自动理解并操作数据库。

### 1.2 核心价值
- **效率提升**: 录单时间从10分钟 → 10秒钟
- **错误减少**: AI自动验证，减少人为错误
- **成本降低**: 减少人工操作成本
- **客户体验**: 24小时即时响应

## 三、技术栈选型

### 3.1 后端框架
- **主框架**: Python FastAPI
- **理由**: 异步支持好，适合AI对话场景，开发速度快

### 3.2 AI模型
- **主要LLM**: 通义千问/Qwen
- **备用方案**: 文心一言、智谱AI
- **理由**: 国内可用，中文理解能力强，支持function calling

### 3.3 数据库
- **主数据库**: PostgreSQL (JSONB支持好)
- **缓存数据库**: Redis (对话上下文管理)
- **消息队列**: RabbitMQ 或 Redis Stream

### 3.4 部署方案
- **容器化**: Docker + Docker Compose
- **云服务**: 阿里云/腾讯云
- **监控**: Prometheus + Grafana
- **日志**: ELK Stack

## 六、数据结构设计

### 6.1 对话会话表 (conversation_sessions)
```sql
CREATE TABLE conversation_sessions (
    id UUID PRIMARY KEY,
    user_id VARCHAR(255),
    supplier_id VARCHAR(255),
    status VARCHAR(50),  -- active, completed, cancelled
    context JSONB,  -- 对话上下文
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.2 对话消息表 (conversation_messages)
```sql
CREATE TABLE conversation_messages (
    id UUID PRIMARY KEY,
    session_id UUID REFERENCES conversation_sessions(id),
    role VARCHAR(20),  -- user, assistant, system
    content TEXT,
    intent VARCHAR(50),  -- 识别结果
    entities JSONB,  -- 提取的实体
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.3 AI处理记录表 (ai_processing_logs)
```sql
CREATE TABLE ai_processing_logs (
    id UUID PRIMARY KEY,
    session_id UUID REFERENCES conversation_sessions(id),
    input_text TEXT,
    output_data JSONB,  -- 输出数据
    confidence FLOAT,  -- 置信度
    status VARCHAR(50),  -- success, error, manual_review
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
